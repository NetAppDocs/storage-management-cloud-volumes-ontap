= Learn about BYOL licensing in Cloud Volumes ONTAP
:hardbreaks:
:nofooter:
:icons: font
:linkattrs:
:imagesdir: ./media/

[.lead]
Bring-Your-Own License (BYOL) is a Cloud Volumes ONTAP charging model in which you pay for capacity consumption through a license that you purchase directly from NetApp instead of through marketplace subscriptions. NetApp supports BYOL for standard and private-mode deployments and for capacity-based and node-based licenses, but BYOL is subject to availability restrictions. Each BYOL license is tied to your company and specific NetApp Support Site credentials, and you can manage BYOL licenses in the *Licensing and subscriptions* section of NetApp Console under *Direct licenses*.

[NOTE]
NetApp has restricted the purchase, extension, and renewal of BYOL licensing for standard deployments with valid marketplace subscriptions. For more information, refer to https://docs.netapp.com/us-en/storage-management-cloud-volumes-ontap/whats-new.html#restricted-availability-of-byol-licensing-for-cloud-volumes-ontap[Restricted availability of BYOL licensing for Cloud Volumes ONTAP^]. NetApp is phasing out node-based licensing in favor of capacity-based licensing, and they remain available in a few older systems, such as USPS customers and deployments in China. For more information, see https://docs.netapp.com/us-en/storage-management-cloud-volumes-ontap/concept-licensing.html#end-of-availability-of-node-based-licenses[End of availability of node-based licenses^].

== BYOL deployment modes

[role="tabbed-block"]
====
.Standard-mode deployments
--

* Instead of BYOL, NetApp prefers annual or pay-as-you-go (PAYGO) marketplace subscriptions for charging your consumption.
* Standard-mode deployments use capacity-based licenses over node-based licenses. Only very few standard-mode deployments use node-based licenses.

--
.Private-mode deployments
--

* Private-mode deployments rely completely on BYOL licenses because marketplace subscriptions are not available in private mode.
* For all new deployments, you should use capacity-based Essentials packages instead of older node-based licenses that were used in previous private-mode deployments. 

--
====


=== BYOL license types and transferability in private mode

Here are the key differences between capacity-based and node-based licenses in private mode:


[cols="25,37,38",options="header"]
|===

| Feature
| Capacity-based licenses
| Node-based licenses

| Deployment support
a| New private mode supports only capacity-based licenses, specifically the Essentials package.
a| New private-mode deployments do not support node-based licenses.

| Purchase
a| Purchase a capacity-based Bring-Your-Own License or BYOL Essentials package from NetApp and assign it to your system during a private-mode deployment. 
a| If you have an existing private-mode deployment with a node-based license, you can convert it to capacity-based licensing by purchasing an Essentials package from NetApp.
| Capacity
a| The first 500 GiB of consumed capacity does not count toward your license charges. You can purchase additional packages as your workload requirements grow.
a| A node-based license provides up to 368 TiB of capacity for a single node or HA pair. To allocate more than 368 TiB to a Cloud Volumes ONTAP system, purchase multiple licenses. For example, two licenses provide up to 736 TiB, and four licenses provide up to 1.4 PiB.

| Scope
a| Capacity-based licensing draws from a shared capacity pool across your Cloud Volumes ONTAP systems, so you can redistribute workloads as your storage needs change. 
a| Each node-based license applies to a single Cloud Volumes ONTAP system and allocates fixed capacity to that system. 
| Transferability
a| Each capacity-based license is associated with a Console account. All systems created under that account can share the license capacity and serial number. You can view the serial number in the Console and assign the same license to multiple systems under the same account. For example, a 5 TiB license can support two systems with 2.5 TiB each or one system with 5 TiB.
a| You can transfer a node-based BYOL license between systems by deleting the existing system and using the same license to create a new one. For example, you might delete an existing licensed system and use the license for a new system in a different VPC/VNet or cloud provider. Only _cloud-agnostic_ serial numbers work across cloud providers. These serial numbers start with the _908xxxx_ prefix.

|===

== BYOL management and renewal 

To renew your BYOL license, contact a NetApp representative. The Console automatically obtains and installs the new license on the Cloud Volumes ONTAP system. If the Console can't access the license file over a secure internet connection, you can download the license file and then link:task-manage-node-licenses.html[manually upload the file to the Console]. 

To manage those credentials, see https://docs.netapp.com/us-en/console-setup-admin/task-adding-nss-accounts.html[Manage NSS credentials associated with NetApp Console^].

== License expiration

The Console displays a warning 30 days before a node-based license expires and again when the license expires. The image shows the 30-day expiration warning in the user interface:

image:screenshot_warning.gif["Screen shot: Shows a Cloud Volumes ONTAP system that includes a warning icon. The icon indicates that an action is required."]

You can select the system to review the message.

If you are an organization admin or account admin and have enabled the option, the Console includes a license expiration warning in the Cloud Volumes ONTAP report and emails it to you.

If you don't renew the license in time, the Cloud Volumes ONTAP system shuts down. If you restart it, it shuts down again.
