= Learn about BYOL licensing in Cloud Volumes ONTAP
:hardbreaks:
:nofooter:
:icons: font
:linkattrs:
:imagesdir: ./media/

[.lead]
Bring Your Own License (BYOL) is a charging model where you bill your capacity consumption through a license purchased directly from NetApp, vis-a-vis charging through marketplace subscriptions. Though NetApp supports BYOL for both standard and private mode deployments and capacity-based and node-based licenses, it is subject to certain restrictions and availability. Your BYOL license is tied to your company and specific NetApp Support Site credentials. You can manage BYOL licenses in the *Licensing and subscriptions* section of NetApp Console under the *Direct licenses* option.

.Restricted availability of BYOL licensing for Cloud Volumes ONTAP
NetApp has restricted the purchase, extension, and renewal of BYOL licensing for standard deployments with valid marketplace subscriptions. For more information, refer to https://docs.netapp.com/us-en/bluexp-cloud-volumes-ontap/whats-new.html#restricted-availability-of-byol-licensing-for-cloud-volumes-ontap[Restricted availability of BYOL licensing for Cloud Volumes ONTAP^].

== BYOL deployment modes

[role="tabbed-block"]
====
.Standard-mode deployments
--

* NetApp recommends marketplace subscriptions (annual or pay-as-you-go) for charging your usage over BYOL.
* NetApp recommends capacity-based licenses over node-based licenses.

--
.Private-mode deployments
--

* Private mode deployments rely completely on BYOL licenses, because marketplace subscriptions are not available for private mode deployments. For information about uploading BYOL licenses to private mode deployments, refer to https://docs.netapp.com/us-en/bluexp-cloud-volumes-ontap/task-manage-node-licenses.html[Manage node-based licenses].
* NetApp recommends only capacity-based Essentials packages over older node-based licenses for private mode deployments.

--
====

== BYOL license types and transferability

[role="tabbed-block"]
====
.Capacity-based licenses
--

* Capacity-based licensing draws from a shared capacity pool across your Cloud Volumes ONTAP systems, giving you flexibility to redistribute workloads as your storage needs change. 
* NetApp supports only the Essentials package for capacity-based licensing in private mode. Purchase a capacity-based Essentials package from NetApp (bring your own license or BYOL) and assign it to your system during deployment. NetApp provides 500 GiB of usable capacity at no charge. After you exceed 500 GiB, you must purchase an Essentials package and assign it to your system. You can purchase additional packages as your workload requirements grow.
* Each capacity-based license is associated with a Console account. All systems created under that account can share the license capacity and serial number. You can view the license serial number in the Console and assign the same license to multiple systems under the same Console account. For example, if you have a 5 TiB license, you can create two systems with 2.5 TiB of capacity each, or a single system with 5 TiB of capacity.
--
.Node-based licenses
--
* New private-mode deployments do not support node-based licenses, except for deployments in China. 
* A node-based license provides up to 368 TiB of capacity for a single node or HA pair. You can purchase multiple licenses for a Cloud Volumes ONTAP system to allocate more than 368 TiB of capacity. For example, two licenses provide up to 736 TiB of capacity, or four licenses provide up to 1.4 PiB.
* Each node-based license applies to a single Cloud Volumes ONTAP system and allocates fixed capacity to it. However, a node-based BYOL license is transferable between systems when you delete an existing system and use the same license to create a new one. For example, you might want to delete an existing licensed system and then use the license with a new system in a different VPC/VNet or cloud provider. Note that only _cloud-agnostic_ serial numbers work in any cloud provider. Cloud-agnostic serial numbers start with the _908xxxx_ prefix.

* Node-based licenses are available for older systems and specific cases, such as USPS customers and deployments in China. NetApp has a phased plan to transition from node-based licensing to capacity-based licensing. https://docs.netapp.com/us-en/storage-management-cloud-volumes-ontap/concept-licensing.html#end-of-availability-of-node-based-licenses[End of availability of node-based licenses^]
--
====

== BYOL management and renewal 

To renew your BYOL license, contact a NetApp representative. The Console automatically obtains and installs the new license on the Cloud Volumes ONTAP system. If the Console can't access the license file over a secure internet connection, you can download the license file and then link:task-manage-node-licenses.html[manually upload the file to the Console]. 

https://docs.netapp.com/us-en/console-setup-admin/task-adding-nss-accounts.html[Manage NSS credentials associated with NetApp Console^].

== License expiration

The Console displays a warning 30 days before a node-based license expires and again when the license expires. The following image shows a 30-day expiration warning that appears in the user interface:

image:screenshot_warning.gif["Screen shot: Shows a Cloud Volumes ONTAP system that includes a warning icon. The icon indicates that an action is required."]

You can select the system to review the message.

If you are an organization or account admin and enabled the option, the Console includes a license expiration warning in the Cloud Volumes ONTAP report and emails it to you.

If you don't renew the license in time, the Cloud Volumes ONTAP system shuts down. If you restart it, it shuts down again.
